1. Setup that worked

  • Hardware: 2× NVIDIA RTX PRO 6000 Blackwell Max-Q (SM120, 96 GB each), no NVLink; nvidia-smi topo -p2p r shows P2P OK. AMD EPYC host (48 threads, 125 GB RAM).
  • Software: Docker image lmsysorg/sglang:inkling-2-mini (sglang 03fde9cc3 + SM120 kernels, torch 2.14.1+cu130, FlashInfer 0.7.4 with sm120f kernels). Note the image is not upstream: it carries SM120-only kernels that upstream lacks, so don't swap in an upstream checkout.
  • Launch scripts (tested end to end): deploy/serve_inkling.sh {tp2|replicas|gpu0|stop}, deploy/serve_deepseek.sh [stop].
  • Only one patch was needed (deploy/patches/sm120_draft_moe.diff, 1 file): the DeepSeek DSpark draft head hard-wired an SM100-only TRT-LLM MoE kernel for its MXFP4 layers; on SM120 it now uses the FlashInfer CUTLASS MXFP8×MXFP4 path (already present in the image for the non-hybrid path).
  • DeepSeek on SM120 requires --moe-runner-backend flashinfer_cutlass. The auto-selected flashinfer_trtllm_routed crashes (cubins exist only for SM100/103/107 — the NVIDIA model card was validated on B200).
  • DSpark draft length is fixed by the checkpoint (num_draft_tokens = gamma+1: 8 for Inkling, 6 for DeepSeek) – not tunable.
  • Method note: perf/kernel work was started on --load-format dummy weights while the 164 GB download ran (the download was Wi-Fi limited at 15–20 MB/s for hours; plugging in Ethernet would help). All headline numbers below were re-measured on real weights.

2. Parallelism results

DeepSeek-V4-Flash-0731-NVFP4 (weights ≈ 79 GB/GPU in TP2)

Step latency, random tokens, 1024 in / 256 out (dummy weights – step cost does not depend on weight values):

config conc 1 ms/token (tok/s) conc 4 ms/token (tok/s total)
TP2 9.74 (98.6) 10.37 (351)
TP2 + EP2 9.70 (99.1) 10.34 (346)
PP2 14.05 (69.1) 16.24 (232)

Same ordering on real weights, real prompts (HumanEval first 40, no thinking, aggregate output tok/s):

config conc 1 conc 4
TP2 96.4 262
PP2 69.0 180
TP2 + DSpark 284.0 470
  • PP2 is slower because a single stream traverses the GPUs one after the other (one GPU's bandwidth), and PP only helps once the batch is large enough to fill both stages.
  • TP2 over PCIe is not communication-bound: the custom all-reduce costs ~10 µs/call, ~1 ms of a ~10 ms step; that is why EP2 (fewer all-reduces) changes nothing.
  • Per-token time is nearly flat from batch 1→4, i.e. a step is kernel-latency-bound, which is exactly why speculative decoding (verify several tokens per step) is so effective.
  • DSpark mean accepted length on real code prompts: 4.3 tokens/step.

Inkling-2-Mini (19.5 GB – fits on one GPU)

HumanEval first 40, reasoning_effort: low, aggregate output tok/s:

config conc 1 conc 4
1 GPU, no spec 148 372
1 GPU, DSpark 307 720
2 GPUs (TP2), DSpark 451 1011
2 × 1-GPU replicas, DSpark 307 per user (2 users) 720 per server
  • For one user TP2 beats one GPU by +47% at batch 1: Inkling is small so TP all-reduces are cheap, and it halves per-GPU weight reads.
  • Mean accepted length on Inkling ≈ 4.1 of 8.
  • If you run several agents/tools concurrently, two independent replicas give twice the aggregate throughput of one TP2 server at conc 1, but each stream is slower.

3. Coding evals (pass@1, greedy, single sample)

Harness: evals/gen.py (chat API) + evals/score.py (programs executed in a --network none container). Verified: canonical solutions score 100% on all four sets. HumanEval+/MBPP+ are EvalPlus (many more tests per task).

model / mode HumanEval+ MBPP+ HumanEval MBPP
Inkling, default effort – – 91.5% 91.1%
Inkling, low 92.7% 83.3% 98.8% 95.3%
Inkling, medium 93.3% 83.1% 98.2% –
DeepSeek, no thinking (default) 83.5% 78.0% 88.4% 88.7%
DeepSeek, low 93.9% 81.0% 98.2% 94.6%

Read this carefully: - Default-effort Inkling "fails" mostly by running past 6000 tokens without answering (14/164 on HumanEval, 23/257 on MBPP – every non-harness failure). low fixes it and is also 2.4× faster (303 s vs 721 s for HumanEval at conc 1, 552 vs 1389 tokens/problem). medium costs 1.5× more tokens for no gain on the harder sets. - DeepSeek without thinking is ~10 points worse; turn thinking on (reasoning_effort: low) for code. - With 164–378 problems, the 95% CI is roughly ±4–5 points, so Inkling-low and DeepSeek-low are statistically tied on these sets. - Caveats: HumanEval/MBPP are saturated and likely contaminated; they say nothing about agentic/repo-level coding (SWE-bench-style) or long-horizon work. Treat as a smoke test, not a ranking. - DSpark does not change accuracy: Inkling default effort 91.5% (DSpark) vs 92.1% (no spec) on HumanEval, within noise of each other (different kernels → different greedy trajectories).

5. Where the time goes (DeepSeek TP2 decode, profile)

GPU is kernel-bound, not launch-bound (kernel time ≈ step time): GEMM/GEMV 56% (FP8 linear ~3.2 ms, MoE grouped GEMM ~2.1 ms, bf16 small-M cuBLAS/CUTLASS-80 WMMA GEMMs ~3.7 ms of ~15 ms), attention 8%, hyper-connection 4%, router 3%, all-reduce 7%. The image already ships an SM120 low-M bf16 GEMV that only triggers for N ≥ 2048; the router/projection GEMMs with smaller N still go to the generic WMMA kernels — that, and the mhc/elementwise kernels, are the candidates if you want to push beyond the current ~10 ms/step (no change was made).

6. Recommendations

Daily coding + assistant (one user): deploy/serve_inkling.sh tp2, send {"reasoning_effort":"low"}, temperature 0 for code, always set max_tokens (Inkling can ramble at higher effort). ~450 tok/s, sub-second tool calls, the 19.5 GB of weights (~10 GB per GPU under TP2) leave ~80 GB per GPU for KV cache and other work.

Several agents / IDE + background jobs at once: deploy/serve_inkling.sh replicas (one per GPU) or run one server on GPU 0 and use GPU 1 for something else (embeddings, image/vision model, a second model).

When to switch to DeepSeek: only for knowledge-heavy or very-long-context work where a 300B-total model is worth 40% lower speed, a 6-minute swap (serve_deepseek.sh, it occupies both GPUs and leaves ~5 GB/GPU free for KV), and no co-resident models. Use reasoning_effort: low; its default non-thinking mode drops ~10 coding points.

Don't bother with: PP2, EP2, or hand-tuning the draft length (fixed by the checkpoint).

Housekeeping: both servers use --restart unless-stopped; run serve_*.sh stop before launching the other model (both want the GPUs). Weights and the image are cached in ~/.cache/huggingface and Docker, so restarts take ~5–6 minutes (DeepSeek) / ~5 minutes (Inkling TP2), dominated by CUDA-graph capture and kernel autotune.
