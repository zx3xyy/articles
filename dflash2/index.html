DFlash 2 不是新的 attention kernel。它是一套无损 speculative decoding 方法：小模型并行起草，大模型一次验收；v2 再用“候选路径选择 + 两 tap 动态卷积”把草稿接得更顺。

01 / BOTTLENECK

瓶颈不是“算不动”，而是每个 token 都要排队

自回归解码有严格依赖：第 i+1 个 token 必须等第 i 个 token 出来。GPU 每次只推进一步，decode 往往是 memory-bound。

Speculative decoding 的关键，是让昂贵的 target model 一次验证多个候选。DFlash 又把“起草”本身从串行改成并行。

03 / WHAT CHANGED

DFlash 2 的两个核心改动

v1 已经实现整块一次预测；v2 不推翻这个框架，而是针对两个失分点做小而准的修补。

A — CANDIDATE PATH SELECTOR

不要只拿每列 top-1，去候选里找一条“接得上”的路

v1 的每个位置独立取最高 logit，单个 token 都合理，拼起来却可能重复或断句。v2 保留每个位置 top-16，用约 256 维的低秩双线性交互对相邻候选打分，再沿预计算分数选路径。

B — TWO-TAP DYNAMIC DEPTHWISE CONV

让每个位置直接混入前一个位置，专治 block 尾部衰减

05 / DON'T CONFUSE IT WITH

四个容易误解的点

把这些边界想清楚，比记住“3×”更重要。

不是 FlashAttention 2

名字像，但解决的问题不同。FlashAttention 优化 attention 的 IO；DFlash 2 优化 speculative decoding 的 draft 质量与并行度。

仍然是 lossless speculation

候选只负责提速，target verifier 拥有最终决定权；正确的 rejection sampling 可保持与原 target 相同的输出分布。

不是任意模型即插即用

需要为目标模型训练并匹配专用 drafter，runtime 还要支持 hidden-state 条件、验证、KV/state 回滚等路径。

不是任何负载都固定 3×

收益取决于任务可预测性、block size、上下文长度、采样参数、batch/concurrency、硬件与实现质量。

06 / SYSTEMS VIEW

从 runtime 看，真正要落地的是一条状态机

下面是简化伪代码，强调数据依赖，而不是某个框架的具体 API。

while not finished:
  ctx = target_features(last_verified_state)

  # one forward: every masked position together
  logits, hidden = drafter(
      anchor, [MASK] * K, ctx
  )

  candidates = topk(logits, 16)
  pair_scores = selector(candidates, hidden)
  draft = choose_path(pair_scores)

  # one target forward verifies the whole block
  accepted, correction = verify(draft)
  commit(accepted, correction)
  rollback_rejected_state()

Target features
小模型不仅看 token，还利用 target 的中间特征来提高草稿质量。

02

Draft cache
并行 block 的位置、mask、KV/state 必须与 target 的上下文严格对齐。

03

Verifier semantics
greedy 时比较 token；sampling 时需做严格的 acceptance / rejection correction。

04

Rollback
草稿尾部被拒后，只能提交接受前缀；混合 attention / recurrent state 的回滚尤其棘手。
